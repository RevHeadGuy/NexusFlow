# Database migrations

NexusFlow uses [Alembic](https://alembic.sqlalchemy.org/) for schema migrations.
The configuration reads `DATABASE_URL` and the SQLAlchemy models from the
application itself (see `migrations/env.py`), so migrations always target the
same database and schema the app uses.

> The app still calls `Base.metadata.create_all()` on startup for the local
> quick start, which creates any missing tables for a brand-new database. For a
> managed or shared database, use Alembic as the source of truth and apply
> migrations explicitly instead of relying on startup table creation.

## Common commands

Run from the `backend/` directory with the virtualenv active.

```bash
# Apply all migrations up to the latest revision
alembic upgrade head

# Show the current revision of a database
alembic current

# Autogenerate a new migration after changing models
alembic revision --autogenerate -m "describe the change"

# Roll back the most recent migration
alembic downgrade -1
```

Autogenerated migrations are a starting point: review the generated `upgrade()`
and `downgrade()` before committing, especially for SQLite, where some
alterations run through Alembic batch mode.
